# Clients

Every [[TSA]] client, one folder each. This is the roster and the entry point — from here you get to any client's deal, their brand work and their delivery state in one hop.

**Why this folder exists with only one client in it.** [[TSA]]'s own note used to say the split into `Clients/` happens "once there are three or more." That was the bolt-on-later pattern the whole vault exists to kill: the structure that scales gets built *before* it hurts, not after the third client has already been filed in three different places. One client is exactly when it costs nothing to get right.

## The shape every client folder takes

```
Clients/
  <Client Name>/
    <Client Name>.md          <- the client note AND this folder's index: the deal, the gates, the scope
    <source contract>.pdf     <- the signed document the note is derived from
    <Client Name> Brands/     <- their brand work, if the engagement includes brand
```

The client note doubles as the folder index. That is deliberate and it is the one place this vault lets a note wear two hats: a client has exactly one master note, and splitting "the map of this folder" away from "what they bought" would produce two thin notes where one full one belongs.

## Folders in here
- **Alex Foods/** — [[Alex Foods]] · TSA's first client. 146,000 EGP total contract: Brand Foundation (20,000, one-time) plus Package A retainer (42,000/mo × 3). Four brands — BeBo, AlRawy, 2MAN and POLEKA — under the Alex Foods master brand. Brand work lives in [[Alex Foods Brands]].

## What goes here as it grows
- One folder per signed client, created at signature, not at the first deliverable.
- A client whose engagement ends moves to `04 - Archive/` whole — folder and all — with `status: archived` set on the client note. See [[Archive]].
- Pricing logic stays in [[TSA]], not here. There are no packages, so *how* a dedicated price gets arrived at is agency knowledge; *what one client agreed* is client knowledge.
