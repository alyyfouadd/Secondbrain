Sessions 1 to 26 wrote "Notes Touched" as `[[wikilinks]]`. Sessions 27 and 28 wrote them as backticked paths, and so did the 19th. **Nobody wrote the rule down, so the switch never propagated backwards and nobody knew there had been a switch.**

They reference notes and files by name now. **Inbound links stay** — `Daily Notes.md` links to each one, which is what fixed their orphan problem in Session 2 this morning. The two fixes are opposite directions of the same rule: **a log is linked to, never from.**
2. **Every folder index now ends with an `**Up:**` line** back to `VAULT-INDEX`, plus its parent where it has one. That took the root index from 1 inbound to 10 and turned it from a spoke into a hub.

It now carries the routing table: what lands here, where each kind of thing goes, the rule that a move updates both indexes, and what deliberately does *not* come through (daily notes, and anything with an obvious home). 10 outbound edges.
4. **Daily notes are `project: tsa`, not `personal`.** The mapping rule said `01 - Daily Notes/* -> personal` unconditionally, which contradicted the "content wins" line directly above it in the same section. These days are almost entirely agency work. A genuinely personal day still takes `personal`.

## Session 4 — 6:55 AM: The drift checker, and why the PDF check had to be line-based

Continuing work started in another session: *"The PDF check isn't marker-aware like the others. Making it line-based so history is allowed."*

**That checker is not in this repo.** Searched all nine remote branches — no check script exists on any of them, so it is uncommitted in that session's own container and unreachable from here. Built it here instead, with the PDF check line-based and marker-aware from the start.

### Why line-based is the whole point

This vault keeps its own history in place deliberately. `Alex Foods Brands.md` line 17 reads: *"`Alex Foods - Design System v1.1.pdf` … *(v1.0 was superseded the same day and removed)*"* — **one line naming both a file that exists and a file that does not**, and the sentence is correct and permanent.

A file-based check has exactly two options on that note, and both are wrong: fail it forever, or exempt the whole file and go blind to real drift three lines below. **Line-based plus a marker vocabulary is the only thing that separates a record from a rot.**

Three categories, not two — the second one only showed up once the check ran against real content:

| Category | Example in the vault | Verdict |
|---|---|---|
| **History** | "v1.0 was superseded and removed" | exempt |
| **Planned** | `Brand Book Spec` § 3: **Delivered as** `Alex Foods — Brand Foundation v1.0.pdf` | exempt — the book is not built yet |
| **Drift** | a note naming a file that should be there and is not | **flag** |

### What it found on its first real run

Seven PDF findings, and they sorted into three genuinely different outcomes — which is the useful part, because the temptation was to widen the exemptions until it went quiet.

1. **Five in the daily notes — false positives, fixed in the checker.** A log is history by construction: *"Built and shipped `Design System v1.0.pdf`"* was true on 18 September and stays true as a sentence about that day. **The filename is the marker**, so daily notes are exempt from the PDF check as a class rather than needing a word added to every line. They stay in all five other checks.
2. **One in `Active Priorities` — a gap in the vocabulary, fixed in the checker.** The line said *"two notes pointed at a **deleted** `Design System v1.0.pdf`"*. "Deleted" is plainly a history marker and was missing from the list. Added, with "never committed" and "not in the vault".
3. **One real defect, fixed in the note.** `Alex Foods Brands` § "The Canva mockup" opens *"A file named `bebo_mucup.pdf` arrived 18 September"* and reads as though the file is in the folder. **It is not, deliberately** — a 9.9 MB Canva deck whose whole value is two images that were extracted and kept, recorded as a decision on 18 Sep and never carried into the note itself. A future session would have gone looking for it. The line now says it is not in the vault and why.

### The self-test, because a check that only says "clean" is worthless

Wrote a note with six deliberate defects and ran it:

- `Ghost Report v9.9.pdf` with no marker → **flagged**
- **the same filename** on the next line with "was superseded and removed" → **passed**
- `**Delivered as** Future Book v1.0.pdf` → **passed** as planned
- `[[No Such Note]]` → **flagged**
- the same broken link inside a code span → **passed**, matching Obsidian
- a `[[wikilink]]` added to today's daily note → **flagged** by the log rule

**Two adjacent lines naming one identical file, one flagging and one not, is the proof.** Test note deleted; vault re-verified clean.

### And then it caught its own documentation

Writing the checker up in `VAULT-INDEX` produced a line quoting **"shipped v1.0.pdf"** as an example of what the log exemption covers. The check flagged it — correctly, by its own rule, which matched any filename in prose.

The lazy fix was an exemption. The right fix was narrower: **checked every note, and every genuine PDF reference in this vault is inside backticks.** Exactly one mention in 46 notes was not, and it was that documentation line. So a reference is now defined as a backticked name, and prose quoting a filename is an example. That removed a whole class of false positive instead of papering over one, and the self-test still bites on all four cases afterwards.

### Decisions Made

- **Built it rather than waiting for the other session to push.** It is unreachable from here, and rule 6 says fix it in the session rather than hand it back.
- **Fixed the note, not the check, on `bebo_mucup.pdf`.** Widening a checker until it stops complaining is how a checker becomes decoration.
- **Daily notes exempt from the PDF check only.** A blanket exemption would have taken logs out of the frontmatter, wikilink and log-hygiene checks too, and the log rule is the one that keeps the graph honest.
- **`.claude/tools/`, not `05 - Resources/`.** It is tooling an AI session runs, not reference material Aly reads — and he has no terminal, so a script in his folders would be a file he can never execute.
